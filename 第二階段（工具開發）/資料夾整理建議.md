> 基準：現行部署方式為 **GitHub + Vercel**，build 指向 `第二階段（工具開發）/`，output 為其下 `deploy/`。
>
> 產出日期：2026-04-15

---

## 一、建議刪除的檔案

以下檔案對目前部署與開發完全無作用，刪除可減少 repo 體積與混淆。

### 根目錄

| 檔案 | 理由 |
|------|------|
| `netlify.toml` | Netlify 遺留設定，已遷移 Vercel，vercel.json 已取代。 |
| `遷移指南_GitHub_Vercel.md` | 遷移已完成，屬一次性文件，留著容易誤導。 |
| `Claude Code_建商資料/` | 裡面只有 `.claude/settings.local.json`，空殼資料夾，無實際資料。 |
| `.DS_Store` | macOS 系統檔，應由 .gitignore 排除（已設定）。 |

### 第二階段（工具開發）/deploy/ 內

| 檔案 | 理由 |
|------|------|
| `_headers` | Netlify 格式的 headers 設定，Vercel 不讀取，功能已由 `vercel.json` headers 區塊取代。 |
| `_redirects` | Netlify 格式的 redirects 設定，Vercel 不讀取，功能已由 `vercel.json` redirects 區塊取代。 |
| `update_html_files.py` | 部署用的 build tool 不應放在 deploy（output）資料夾裡，移出或刪除。 |

### 第二階段（工具開發）/ 內

| 檔案 | 理由 |
|------|------|
| `執行策略/old/` | 含 V1、V2 策略舊版、舊定位分析（宅策），已被現行策略文件取代。 |
| `執行策略/我的決策性格/第一個選擇_v2_設計規格.md.bak` | 備份檔，正本已存在，不需要 .bak。 |

### 第一階段（內容站）/（整個資料夾評估）

| 項目 | 大小 | 建議 |
|------|------|------|
| `archive/` | **13 MB** | **強烈建議刪除**。含 6 版舊前端、舊後端、style experiments、zip 檔。全部是已淘汰的 HomeRUN 時期程式碼，佔了 repo 75% 體積。如需保留歷史，git history 已有紀錄。 |
| `archive/old-backend/__pycache__/` | — | Python cache 檔，應已被 .gitignore 排除，若仍在 git 中應移除。 |
| `deploy/` | 3 MB | 第一階段網站快照。若不需要回顧舊版網站外觀，可刪除。 |
| `build-css.sh`, `inject.py`, `input.css`, `tailwind.config.js` | — | 第一階段的 build 工具，Vercel 不會觸及，純備份用途。 |

## 四、額外建議

1. **`deploy/line-auto-reply.md`**：這是 LINE 自動回覆的設定文件，放在 deploy 裡會被 Vercel 當作網頁公開。建議搬到 `Line經營/` 資料夾。

2. **builder-*-full.html 與 builder-*.html 並存**：目前有 4 個建商同時有兩種版本（一般版 + full 版）。如果 full 版是最終版，可以考慮只保留一種，減少維護負擔。

3. **`builder-template-reference.html`**：如果這是開發用的範本而非公開頁面，建議移出 deploy。

4. **.DS_Store 清理**：雖然 .gitignore 已設定，但如果先前已 commit 進 git，需要執行 `git rm --cached` 來移除追蹤。
